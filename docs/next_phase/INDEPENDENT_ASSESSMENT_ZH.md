# 独立研究判断与下一阶段执行依据

日期：2026-10-13。本文完整阅读用户诊断文本（411 行）和研究路线图（117 行）后形成；加入了原始代码、1648 条在线记录的复核与公开论文方法核查。旧研究的冻结主结果和发布包保持原样。用户随后要求连续完成 18 周安排，执行记录另见本目录 `EXECUTION_LEDGER_ZH.md`。

## 1. 我的判断

保留平台，放弃旧成本控制器作为论文主方法。风险准入方向有必要，但「风险阈值 + 多动作 + 缓存复用」还不足以成为高水平论文的新贡献。真正应先回答的问题是：当前候选答案出现错误时，增加哪一种计算能可靠修复——在同一个推理状态再次读出，还是推进推理状态？两种计算的收益、风险、成本必须用配对干预比较，不能用更复杂的分类器代替证据。

我的优先方案是**与实际候选答案绑定的计算分配**：先产生一个短候选答案并保存它的身份，再依据这个候选的读出稳定性和未来修正风险，选择直接交付、追加短读出、继续若干段落或 FULL 回退。提交时交付被检查的同一个答案，不能检查 A 然后重新采样 B。风险校准覆盖这个完整策略，包括重读、选择答案、反复检查和最终提交。

这是待验证方案。现阶段不能声称首创，更不能声称已经获得性能改善。若「候选绑定」只是实现修复，或简单固定预算/DEER-PRo 已覆盖收益，就不能将它包装成论文核心贡献。

## 3. 本次已经完成的原始数据审计

重新运行 `validate_study_artifacts.py`、`audit_online_trajectories.py`、`diagnose_online_failures.py`，再次核验 1648 条记录、固定模型和生成源码、题目划分、逐题配对及共同前缀。所有实际观测的前缀匹配，相同上下文的答案一致；未发现可解释主损失的缓存污染证据。这不是所有精度、模型和长度的通用保证。

新增 `scripts/audit_next_phase.py`，导出了主模型 25 个有害、4 个有益结果及第二模型 2 个有害结果，共 31 行完整矩阵。包含题目、标准答案、实际输出、最后推理片段、风险预测、成本惩罚、STOP margin、触顶状态与时间。无法从答案确定的原因保留 `unknown`，不把数值差一位自动归因为四舍五入。

主模型原控制器终止 STOP 共 211 题。对这些**已经观察的终止状态**，原 `full_fix` 识别有害停止的 AUC 为 **0.633**，`1-p_stop` 为 **0.702**。第二模型仅 10 个 STOP/2 个有害，样本太少，不能将其排序统计当作可靠迁移估计。这一审计不能用来选择新最终阈值。

**表中新增行全部是旧记录拼接诊断。**否决时取已保存 FULL 答案；没有在 GPU 上恢复该状态、执行后续决策或测量新策略耗时。时间列取不同运行的已记录成本，不包含新的否决、恢复与探针开销，也不是严格时延下界。不能报告为「新策略准确率 88.67%、加速 10.88%」。Oracle 行使用金标准，仅说明这批已采样结果存在选择空间，不证明可以学到。

一个直接结论是：**只加 0.9 阈值，可能恢复质量却失去大部分收益，且不能迁移保证。**第二模型的两个有害 STOP 都通过了 0.9 阈值。应将阈值作为必要弱基线，而非预设主方法。

还发现旧独立概率头缺乏联合一致性。在 211 个 STOP 状态中，18 个 `full_fix > 1-p_stop`，1 个 `full_harm > p_stop`；`p_full-p_stop` 与 `full_fix-full_harm` 的平均绝对差 0.0295，最大 0.1693。没有同一个联合分布同时满足这些预测。这是独立拟合的建模局限，尚不是造成某一道错误的已证实原因。下一轮用联合四态模型作必要消融，不声称这种标准建模方法本身是创新。

检测器均值 0.654 秒，逐 token 采样/特征计时均值 1.648 秒，短答案读出均值 0.321 秒；这些墙钟计时并非独立 CUDA kernel 归因。它们支持尝试有限重读，但不保证新数据上的开销同样小。

## 5. 我建议检验的三个可证伪假设

**H-A：被检查答案与被提交答案的一致性。**给相同前缀生成固定候选 A，对 A 计算答案类型完整性、答案 token logprob、候选一致性与风险特征；若提交，原样提交 A。对照是检查状态后另采样答案 B，及单次试答绑定。若绑定只是避免多一次采样且改善不显著，将其归为协议约束，不作为贡献。

**H-B：重读与续写的相对价值。**同一前缀上比较短答案重读、1 段、4 段和有界 FULL。记录各动作相对固定候选的联合修正/改错、真实增量时间，以及重读和续写带来的正确率差。预测器需要在问题隔离验证中区分两类动作，且在线胜过始终重读、始终续写和固定预算；否则不训练更复杂动作网络。

**H-C：质量准入后的有效选择。**使用联合四态预测保持边际一致，但最终只用独立、完整策略级校准认证风险；成本不允许取消必要的风险准入。测试是否保留较大安全停止覆盖，而非退化为全部 FULL。若风险约束导致几乎不早停，应如实报告，无需用「安全」掩盖零效率收益。

## 6. 随机性干预如何真正区分两种计算

同一固定前缀 s 和固定候选 A，续写动作 a 的第 r 个推理随机种子产生状态 s_ar，最终读出种子 e 产生 Y_are。先在开发/pilot 状态做完整交叉的 r×e，而不是每次同时换两个种子。不同动作尽量用共同随机数，推理和答案分开计数；训练/选择/校准/测试按题目隔离。

估计 `E[Y_a]-E[Y_STOP]` 与实际候选 A 的相对风险；同时估计 `Var_r(E_e[Y|r])` 和 `E_r(Var_e[Y|r])`。如果各 r 的读出种子互相独立，组均值的方差需要减去 `within_readout_variance/m`。本方案为配对比较采用相同读出种子完全交叉各 r，不能沿用这一嵌套修正：改用双向随机效应 ANOVA，推理分量为 `var(row_means)-MS_interaction/m`，读出分量由读出种子主效应与交互项构成。负估计保留，不能裁零后当作没有变化。只采 2 个 r 时估计很不稳定，当前取至少 3 个，并报告问题聚类区间。

这套干预识别的是**指定读出协议、采样和模型的操作性效果**，不是直接测量模型内部因果推理或认知机制。候选一致可能稳定地错误；投票选中众数不自动增加正确率。

首个机制 pilot 可从 24 道题 ×2 个不同长度检查点起步，共 48 状态。STOP 每状态 3 个读出；DEFER-1、DEFER-4、FULL 各 3 个推理种子 ×3 个读出，共 `48×(3+3×3×3)=1440` 个短答案读出及 `48×3×3=432` 个续写分支。它不是只有「48 次推理」。先测实际吞吐与触顶情况，再决定是否扩展；无足够检查点、未完成段落和超限状态都记录，不能静默剔除失败。

## 7. 风险目标、样本量与不可混淆的保证

主目标为 `min E[T_policy]`，约束 `E[Y_FULL-Y_policy] ≤ ε`。保守准入可用 `H=1{Y_FULL=1,Y_policy=0}`，因为净损失不大于有害率。FULL 是同协议有界参照，不是所有问题正确的 oracle。

对一个事先冻结策略、独立同分布/适当交换性的题目，在 n 题观察 h 个有害，用单侧 95% Clopper–Pearson 界 `Beta^{-1}(0.95; h+1,n-h)`；零事件时为 `1-0.05^(1/n)`。若在同一校准集认证 K 个预声明候选并选择，用 α/K 形成同时界，或者在独立选择集先选一个再独立认证。

| 独立题目 n | 候选 K | 观测有害 h | 含义 |
|---|---:|---:|---|
| 50 | 1 | 0 | 上界约 5.82%，不能认证 1pp。 |
| 299 | 1 | 0 | 才首次达到 ≤1%；299 是零事件、单一冻结策略的理想最低数。 |
| 400 | 1 | 0 | 约 0.746%，可认证指定总体的有害率。 |
| 400 | 8 | 0 | 同时界约 1.261%，仍不够。 |
| 505 | 8 | 0 | 零事件时才首次达到 ≤1%。 |

已经看过旧测试后做诊断，不能再给这些重放行作无选择偏差的新认证。一个问题的多个种子/检查点是相关观测，不增加同样数量的独立 n；需问题聚类处理或每题预声明一个随机试验。每个模型/任务的分布转移另报告，不能共用一个合并风险界掩盖小组失效。

模型判分与符号解析也有误差。1pp 的推理性能保证需要足够可靠的判分证据，不能以官方模型评测约 95% 一致率替代。所有修正/改错对人工审阅，两种方法共同判错/判对的随机样本也抽查；有争议保留区间敏感性。新数据生成前冻结评分规则；不因某种方法受益而临时修改评分。

## 8. 执行时的论文准入条件

第一道门槛：新数据的可评测性、非平凡 FULL 正确率和可控触顶；主体同时包含可解题和难题，不能靠大量两种策略都错的题获得表面低风险与大节省。

第二道门槛：机制标签有可预测性，且一个最小策略在全新选择集优于充分优化的固定预算、单次试答和重复试答；报告正确题/错误题上的节省与风险，避免总体均值掩盖仅节省失败题。

第三道门槛：独立风险校准通过，冻结主策略，真正运行新的盲测、第二模型、跨家族模型与可验证非数学任务。若未通过 1pp，不把经验性能改名为认证；允许报告目标 2pp 的另一个预声明运行点，但不能在看测试后替换主目标。

第四道门槛：只有算法质量—耗时前沿成立，才进入并发服务。Serving 必须实际计入探针、答案、prefill、KV 分支、队列、显存与调度干扰。单请求秒数不能证明吞吐或 goodput；吞吐提升也不能抵销不合格质量。

高水平论文应最终形成一条可审查链：**失败机制 → 配对干预验证 → 有必要的动作选择 → 冻结风险控制 → 强基线与跨域优势**。无论机制假设的结果好坏，都保留全部原始数据与失败，按阶段门槛决定继续或转向。
