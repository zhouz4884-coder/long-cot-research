# 候选绑定与风险约束计算分配：方法和证据约束

本文是后续实现与验收的约束，不是已取得的新性能结果。实际进度见 `EXECUTION_LEDGER_ZH.md`。

## 状态、动作与交付

状态只能包含问题文本、已经生成的 token、当前 KV 状态、当前候选答案及实际运行元数据。Gold、未来 token、未来判分不得作为在线特征。数据集人工难度不能被悄悄作为部署时可获得的信号。

先产生候选 A0，保存其上下文、token IDs、原始交付文本三种哈希。COMMIT 的文本必须与这个被检验候选完全一致；协议级展示包装需事先冻结，不能在通过检查后再采样另一个答案。读出在副本缓存上进行，主推理缓存不改变；自然结束与强制结束分别记录。

最小 M1 只做「检查实际候选 → 质量准入 → COMMIT 或有界 FULL」，用它检验候选特征/联合风险是否有必要。M2 在 M1 的新数据前沿成立后加入 READ_MORE、DEFER-1/4 与实际毫秒成本。稀疏检查、多动作与联合四态均不是单独的新颖性主张。

READ_MORE 的追加答案仅在同一前缀上生成。聚合/选中候选的规则事先固定，不能使用 Gold 选择。风险训练对象要对应选中的候选，FULL 参照答案也固定为主协议的参照种子；不能把「选中 Aj 对 FULL_j」混当「选中 Aj 对 FULL_0」。完整策略独立校准覆盖重复读出、选择、反复检测、回退与交付。

DEFER 的软边界采用操作性自然段落与平衡定界符，不等于证明完成了一次有效数学推导。指定段落数未完成就触及硬 token 上限时必须记录，不删掉这类状态。推理种子和答案种子独立，跨动作用共同随机数；调用顺序不能改变随机流位置。

## 联合预测与成本

四态为当前固定候选/后续动作的 00、01、10、11。STOP 相对动作的有害风险是 01，收益是 10；反方向名称不复用旧变量误导读者。所有边际与净增益由同一四态分布得到，避免不相容的独立概率头。有限样本/分布转移的不确定性仍由独立校准审计，不能从四态一致性推出可靠性保证。

代价只在 COMMIT 准入和后续动作选择规定的范围内参与优化。直接按下一个动作的耗时最小会总选短步，不能因此声称最优动态预算。M2 必须同时比较动作的预测质量变化、等待及再次检测代价，给出完整策略消融；复杂 SMDP/强化学习在有价值信号前不开发。

每次生成的计算都计费。至少分别记录主推理 token、所有侧读出 token（包括被拒绝的候选）、最后新增答案 token、探针输入 token、额外编码器输入以及缓存复制/恢复开销。交付的候选已经生成，不能再次将同一批 token 计费，也不能把被拒绝的侧读出退回成本。`compute_generated_tokens` 与 `delivered_tokens` 分开。

真实端到端 wall-clock 包含实际在线特征、检测、读出、缓存复制、等待和提交。离线动作银行的轨迹计时与保存记录拼接都不能替代新策略在线时延。模型加载和 warmup 单列；评分是否在线必须明确，私有测试判分只用于离线评价。

## 数据与统计

Omni-MATH 版本1为 pilot100/dev608/selection304/calibration912/test1218。pilot发现未提供几何位置条件后，统一输入质量筛查排除95个正式候选，版本2正式pool2947，划分dev589/selection294/calibration884/test1180。旧pilot100和原版本保留，正式数据尚未生成。只对限定的有限数值、文本可用子集作主张，公开覆盖率及排除清单。所有问题与全部种子/检查点按 Problem ID 隔离；已观察 MATH-500 不再作为新盲测。

版本3再增加整个Gold纯数值表达式的前置语法筛查，因为pilot的无限解族/散文Gold被解析器部分抽取为单个数字。统一排除260个正式候选，当前冻结dev537/selection268/calibration806/test1076，正式pool2687。版本1/2不覆盖；旧pilot评分只作协议诊断，已标输入问题不用于主数学性能结论。单纯“Gold自己与自己判相等”不可作为任务类型验收。

版本4再排除35个估计/部分计分任务。当前正式划分为dev530/selection265/calibration795/test1062，pool2652；旧版本均存档。主指标是精确数值任务的统一判分准确率，不将估计任务原本的分段奖励压成一个未经声明的二元分数。

策略级有害风险采用独立题目单侧置信界；多阈值需同时界或独立选择。交叉 R×E 的方差采用交叉随机效应估计。重复种子增加每题测量精度，不增加相同数量的独立题目。所有稀少风险分层给出样本数，不能将零观测当零风险。

必须优化固定预算前沿。若新 pilot 显示 8192 大量触顶，先做预声明的更长预算与原生答案敏感性，再冻结正式参照。只保持一个低质量、截断严重的弱参照不足以支持高水平论文；任何预算调整在最终测试生成之前完成，旧 pilot 保留。

## 基线与任务边界

同协议受控适配、作者原始实现、仅论文报告数字分开列出。DEER 原生读出和 Qwen 特殊终止条件不得在适配中悄悄消失；若完整原生基线不能执行，就明确说明差异，并提供足够强的重复试答对照。Conformal preliminary 接口缺陷单独修复存档，不能据此判定论文方法无效。

LiveCodeBench 官方当前所取 v6 增量为 175 题，时间为 2025-01-04 至 2025-04-06；不能虚称 2026 新题或全部晚于模型训练/发布。需要准确的发布时间过滤和污染边界说明。代码任务使用独立代码提示/结束/执行协议，不能沿用数学 boxed finalizer；175 题也不足以在零有害时认证单一策略 1pp 总体风险。

后续生成代码只在隔离、禁网络、只读与资源限额的容器中执行，判分答案不暴露给在线控制器。无真实执行结果就不报告代码 pass@1。Serving 仅在算法阶段通过后做，报告实际负载、goodput、分位时延和调度干扰；单请求节省不等于服务吞吐提升。
