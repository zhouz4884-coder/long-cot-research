# Phase5-C阶段收尾：用了什么、测了什么、结果与问题

2026-11-06。**本阶段试验已完整结束；当前自动候选投影版本未通过扩大门槛。**

总目标仍是提高长思维链最终解题质量。本阶段的具体目的是：在扩多模型、多数据集前，用足够多的不同自然题，检验“目标提示＋自动候选投影”是否胜过强读出基线，避免凭几个合成状态定方法。

## 实际用了什么

- 模型：1个固定Qwen3-4B checkpoint，两个3090副本并行；FP16/SDPA、greedy、batch最多2。
- 数据：旧300题开发池排除已诊断P1的100后，按固定ID哈希选32；不按对错/cap挑题。32题干和trace无字面重复，6个subject仍是1个历史来源。
- 历史：各题已有1088–8192-token思考，原协议还含独立forced读出。本轮重新编码引用文本，非新native端到端解题或旧cache精确重放。
- 候选：题干目标提示K＋最多1800字符/8段的自动候选摘录E。E全部UNVERIFIED；25题类型unknown，没有真值G、认证自然父边界或终局映射。
- 对照：完整历史、目标提示、同一E的完整历史、固定尾窗、开放boxed前缀与从题干独立重算，共7条件。

## 问题在哪里

1. **紧token保护影响交付。** 224输出中109触384顶；这是固定终局预算比较，不能当不受长度限制的数学能力排名。
2. **读出起点不同。** 开放boxed与FullContinue的system/user相同，仅assistant预填不同，前者修复12题、伤害0。下一步应做同阶段、同证据的2×2，而非只给候选更有利格式。
3. **投影仍未解决支持可信性。** 没有自然G，摘录可能漏条件或保留错候选。即使同自由读出阶段，它也净损失5题，不能全归于前缀差异。
4. **解析契约仍过严。** Projected唯一EOS失分C006已算出正确boxed10，但后跟英文名词被拒；其余18失分均触顶未交付。不能说成19次数学算错，也不事后补分。
5. **输入压缩不等于质量增益。** 比同候选完整历史少82.57%输入，输出却多7.43%。本轮不提供单方法延迟或热KV加速结论。

## 已决定与未完成

下一轮按用户要求**取消紧token上限作为质量主条件，正常生成到EOS**；上下文/失控重复等技术保护单列。GPU时间以完整固定矩阵为先，不再由主任务用短研究时限反复留下partial。旧384结果保留，不能补尾巴后覆盖。

先在单模型厘清读出阶段、解析与可靠支持，再用新的独立题确认；之后才做约3模型、约3独立基准与强方法完整native比较。现在还没有多模型、多数据集、自然无限长度或完整GC-PBP有效性的证据。
