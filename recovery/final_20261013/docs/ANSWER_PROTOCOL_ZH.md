# 统一短答案协议与格式失败修复

真实首例在 4096 思考 token 后追加 `</think>\n\n`，模型重新写步骤，192 个答案 token 内没有最终答案。Math-Verify 默认解析器从中间式提取了数字 6；这不是已经给出的最终答案。本例正确答案是 30 度。

同一冻结前缀改用 `</think>\n\nFinal answer: \boxed{` 后，模型先输出 `30}`，随后又继续解释。真实 KV 在 128 token 检查点上也可以输出 `30}`。这两个实例只能证明答案提取协议影响很大，不能证明研究方法普遍有效。

统一修正如下：所有主实验动作、FULL 对照及在线基线都使用相同提示；答案生成在第一个完整外层 boxed 花括号闭合时停止，保留 192 token 硬上限。输入提示中提供的 boxed 开头属于输入，不计为生成 token；最终文本重建该开头后评分。原始生成 token IDs/text 另存。缺失完整答案标记的中间推导不能被当成最终数学错误来解释，单独记为 parse_failed/missing_complete_final_answer。

主评分对象是这个预先约定的单个完整最终答案，不在生成之后用真实标签挑选多个答案。统一协议本身是工程修正，不能声称为论文创新。必须加入同协议 zero-thinking/fixed-budget 对照，防止把格式改善归功于收益预测器。
