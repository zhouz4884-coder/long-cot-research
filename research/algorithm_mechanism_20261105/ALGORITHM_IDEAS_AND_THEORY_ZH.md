# 借鉴文献后，我们准备怎样设计新算法

2026-11-05。依据：用户新提供的第三方意见，以及本轮原文检索、独立数学审查和CPU控制。目标是形成能够改善最终解题正确率、具有独立技术增量的候选算法，并用可复核证据判断是否值得推进高水平论文。组合创新可以成立，但模块名称或组合本身不能替代技术差别和实际收益。

本轮已完成意见阅读、文献/理论审查与CPU反例，没有新增LLM生成、GPU实验、P1百题语义标注或模型训练。附件末尾的实验安排作为建议分析，没有自动成为执行指令。

## 1. 目前是算法问题吗

**可以确认当前粗粒度控制策略有算法层面的不足；还不能把全部错误归结为一个已识别的“阶段指针”缺陷。**

| 层面 | 当前证据 | 能够得出的判断 |
|---|---|---|
| 工程接口 | 原P0禁读/因果mask、缓存隔离、恒等路径与独立数值复算通过；格式问题已单列 | 没有证据把主要差异归咎于尚未修复的mask工程错误。新渲染/新协议仍需自己的接口验收 |
| 控制算法 | 未核验修订就强制删段、没有版本/父依赖检查、删掉正确支持会受损 | 核验、失效范围和重推调度需要明确设计 |
| 模型行为 | 出现把新x放进要求y位置的输出，也有旧值复用和其他算术错误 | 值—角色绑定、复合规则承接、上下文干扰均值得研究 |
| 内部机制 | Late与Fresh的真实状态/输出不同；尚无独立stage表征定位或选择性干预 | “进度指针未回拨”是合理候选假说，尚非已发现病根 |
| 自然任务重要性 | 100条历史样本已固定，尚未完成语义标注 | 不能从人工16例宣布该问题普遍或具有某一发生率 |

“输出跳过了y”也要谨慎：正确地直接计算g(f(x))是合法策略；即使输出g(x)，也可能在内部算过f(x)，只是读取最终操作数时绑定错了。修复算法可以先针对可观察的行为失败，不必等待一个唯一内部故事成立。

## 3. 我优先建议的主算法：版本一致的局部重推

算法描述为“**核验修订 → 撤回旧值版本 → 按完整依赖前沿重推 → 必要时重构工作状态**”。先做训练无关的协议，不同时增加steering、训练赋权和自定义KV核。

### 3.1 状态表示

把三种对象分开：

- 规则F：题目给定且仍有效的关系，例如y=x−9、z=2y；自然推理中由模型推得的规则要另记依据，不自动当可信原题。
- 值及依据：x@1=28；y@0=15依赖x@0；z@0=30依赖y@0。父值/规则版本变化后，旧断言不得冒充当前值。
- 工作文本/缓存K：指定文本、position、mask、backend的数值状态，不等同于符号真值表。

### 3.2 一次修订怎样处理

1. **先核验。** 候选R在隔离分支或保留pre-R检查点的路径中产生。依据可信且充分的约束把它分为接受、拒绝、未知；仅有语言模型似然偏好属于启发式支持，不能冒充证明。新值错也不说明旧值对。
2. **建立新版本。** 接受x_new后，撤回旧x版本及其可能失效的传递后代；保留独立支持和仍有效的定义规则。若变更的是规则，也要撤回依赖该规则的值。
3. **维护完整待重算集合。** 每次只选择父值均已是当前有效版本的节点。线性链可以从y开始；一般DAG可能同时有a、b，不能算完a就跳到汇合z。
4. **显式绑定下一步。** 给模型一个只含已知信息的工作帧，例如：

```text
当前有效：x@1=28
仍有效的规则：y=x−9；z=2*y
旧y、旧z已失效，不作当前依据
本步目标：y@1
本步父值：x@1=28
请先给出 y 的代入式和值
```

没有预先给正确y=19或z=38；若工具实际算出这些值，应作为外部计算计费，并给同工具基线同样权限。

5. **验收再接入。** 检查输出的目标变量、父版本、代入关系和可核验数值。通过才接入当前状态并推进前沿；失败时按预定小预算重试/重构/回到可信状态，不把未核验输出当作已完成节点。
6. **缓存处理后置。** 第一版先比较普通Full+工作帧。只有旧上下文在相同提示下仍造成增量伤害，才测试同可见信息下的Late/Fresh重构。候选R被拒后，必须丢弃候选分支或恢复pre-R状态；改一个reject标志不能撤销已经进入KV的R和后继影响。

```text
on revision proposal R:
    verdict = verify(R, trusted rules and current parent versions)
    if verdict is not ACCEPT:
        restore trusted pre-R state, or rebuild if no certified state exists
        continue without certifying an unverified old/new value
    else:
        install accepted new version
        retire superseded versions and affected descendants
        while required dirty nodes remain and budget remains:
            ready = nodes whose required parents are current and valid
            choose one ready node; expose its rule and parent bindings
            propose -> check -> commit only a valid result
        return final answer only when its required support is valid
```

这是可实现的候选协议，不是已运行的LLM算法。其技术重点是**版本读约束和依赖前沿**，而非把“多写一句推理”重命名。前沿提示也可能只是有效的self-ask式分解；必须通过消融证明新增版本管理有用。

### 3.3 什么可能构成我们的贡献

1. 问题与数据：界定自然修订中的旧值复用、变量错绑和错误改口，展示它们与普通组合题失败的差别。
2. 算法：把修订核验、版本一致的读约束、局部前沿调度结合，改善修订传播并减少误撤回/无谓重推。
3. 模型证据：解释哪些改进来自绑定/读出、哪些来自历史编码路径；若谈stage机制，再做独立干预识别。
4. 实际收益：在同模型、同工具和相同总预算下提高正式数据集正确率，或在同质量下减少完整成本。

这些是候选贡献，尚待自然发生率、最近邻排查和效果实证。完全已知AST的toy可被普通解释器全部算完，不能把该正确率当作LLM算法贡献；PAL、普通self-ask/规则提示、全量重推和无版本管理的局部重推都应是基线。

## 4. 数学上能保证什么

令依赖图为有限纯函数DAG，节点v满足v=f_v(pa(v))。更新的可信根集合为S，可能失效集合取I=Desc*(S)，其中包括被替代的旧根版本。安装已认证的新根后，令C为已完成重算集合：

\[
\mathcal F(C)=\{v\in I\setminus C:\text{全部父值及规则均为当前有效版本}\}.
\]

若图/规则完整正确、未变根可信、新根正确、每步精确执行或经sound checker验收，并覆盖全部必要节点，则保留I外的值、重算I内的值，最终等于从头精确计算。证明是按拓扑序归纳：未受影响祖先不变；每个重算节点的父值与新鲜计算一致，所以本节点也一致。

这说明协议在限定符号域可有**部分正确性**。若由未核验LLM完成每步，保证不成立；若有checker但模型一直给不出合法步骤，则不保证完成率或固定时间。父版本一致也是必要条件，单有版本号不保证数值/规则正确。

几个已执行的CPU反例说明为什么要这些条件：

- `a=x+1,b=3x,z=a+b`：x由1改2，只重算a并读旧b得6；完整前沿得9。
- 局部约束x²=1允许−1，但全题另有x>0时仍错；局部通过不等于全题认证。
- 合法归一化语言概率可给错误x=5更高的文本似然，正log-ratio不能证明x=2+2。
- x−x的值在x改变后不变：有依赖路径表示需要重新验证，不等于旧数值一定错，更不证明旧KV数值等价。

三个精确程序的675组有限根更新已全部匹配冷计算；它验证受限参考实现，不是LLM或自然语言验证器的成绩。详见 `vtfr_formal_audit.md`。

## 5. 从Transformer原理看，为什么这些错误可能出现

简化地，因果Transformer某层有：

\[
k_i^\ell=W_K^\ell h_i^\ell,\quad v_i^\ell=W_V^\ell h_i^\ell,\quad
o_t^\ell=\sum_{i\le t}a_{ti}^\ell v_i^\ell.
\]

残差、归一化、位置旋转等细节不改变此处要点：后位置的h/K/V可依赖前位置。追加“x现在是28”不会在架构层自动改写先前状态，也没有保证同步更新所有角色绑定、派生值和操作选择的硬件寄存器。

Late屏蔽B的key只阻断后续对这些行的直接读取；U/R的旧表示可能已经受B影响。Fresh从开始屏蔽后重新编码，得到另一计算历史。这解释为何一般状态差异合理，却不定位“旧28”或唯一“stage”部件。

现有表型至少兼容：最近数字启发式、变量值检索错绑、普通组合计算失败、旧派生值承接、操作/前沿表征未同步，以及读出提示诱导；它们可以混合。Binding ID和Mixing Mechanisms提示我们把值、身份、位置、角色分开；Iteration Head说明可以在受控任务中识别迭代算法，但不能直接推给Qwen3。

本轮还构造了三个高层程序：一个保留错误阶段；一个实际算出f(x_new)却从错误槽位读取x_new；另一个只取最近数字和外层算子。16个输入上三者都能给g(x_new)签名，其中19个历史输出与该签名兼容。**这不把19个输出标成某机制**；它只说明匹配该签名无法判定模型到底没算中间步，还是算过但绑定错了。

若以后研究stage机制，需要让这些假说给不同反事实预测：交换变量名/角色、改变无关数字新近性、相同数值不同完成阶段、相同阶段不同数值。probe需跨变量名/数值/模板测试并排除位置/答案泄露；选择性双向patch应改变下一操作而保留目标任务自己的值，不能从source顺便复制正确y/z。此要求来自因果抽象和activation patching的研究范式，不是现在已经做过的定位。

## 6. 第二条候选算法：用经核验的状态转移指导训练信用

可以借鉴附件的prop锚点，但我会把训练对象扩为**该推进时推进、该拒绝时拒绝、无需变化时保持**：

\[
L_{trans}=\mathbb E_{B'}[-\log p_\psi(a^*_{state}\mid\text{修订前缀与可信证据})].
\]

a*是经核验的下一状态动作/派生步，包含目标变量及父绑定；正确修订样本可监督第一次有效传播，错误修订样本监督拒绝/回到可信依据，无变化样本监督保持。无法核验的样本记unknown，不能给强标签。纯prop正例目标也值得作对照，但它不会自动学会拒绝错误R。

首先比较**相同已核验数据上的普通SFT**。只有过程目标有价值且普通监督仍有不足，才加入VCORE式赋权：

\[
g_j=\nabla_\psi L_j(B'),\quad
s_t^{(j)}=\langle g_j,\nabla_\psi\ell_t(B)\rangle,\quad
q_j\in\arg\max_{q\in\Delta}\sum_tq_ts_t^{(j)},\quad KL(q\Vert u)\le\delta.
\]

j可分别为全链、最终答案、prop或状态转移。ψ是明确的trainable子空间；q停止梯度，B/B′/H按问题隔离。所有方法必须看到同一批已核验/纠正后的训练材料，否则提升可能只是多了正确标签，不能归功新赋权。

**应收紧附件的四个数学表述：**

1. 不同目标不等于正交。全链梯度本来就包含答案/prop贡献；应测Gram/cosine，不能把Gram–Schmidt的残差仍叫原prop梯度。
2. 固定n时，KL(q||u)=log n−H(q)，同KL确实控制Shannon熵，并可消除纯正仿射分数缩放；它不固定ESS、梯度方差或更新norm。常数分数无法用温度调出正KL；m个并列最大时正温度族极限为log(n/m)。
3. 同LoRA参数步长不等于同有效ΔW或同输出策略KL。还可能出现加权梯度为零，无法归一到正步幅；这些失败必须保留。
4. 原Gibbs解优化固定学习率下的线性对齐g·G(q)。若再令Δψ=−cG/||G||，目标变为g·G/||G||，分母也依赖q；不能继承原线性最优性。同norm可以作为实验控制，两种更新口径需分列。

对局部M-smooth的独立验证损失：

\[
\Delta L_H\le-c\langle\nabla L_H,d_j\rangle+\tfrac12Mc^2,
\qquad d_j=G_j/\|G_j\|.
\]

正确的参考方向、同KL和同norm都不能自动使第一项足够为负。若参考与验证梯度误差≤ε，额外还要付cε的不确定项；当前没有估出这种泛化界。H上的一次NLL下降也不是最终生成正确率保证。

本轮平滑CE反例中，优化“接受正确修订”的prop目标使其loss下降约0.04875，同时错误修订拒绝loss上升约0.05125。这说明W保护必须进入目标或独立约束，不能靠“prop span都是正确的”推出来。完整代数控制见 `transition_anchor_math_audit.md`。

这个方向的候选贡献是状态动作/传播对象与可核验标注、以及实测信用分配增量；过程监督、目标梯度和答案锚定已有前人工作，不能只换名字宣称创新。

## 7. 怎样做一个不会混淆原因的最小实验

先建立基础能力对照：P-only、P+正确修订、P+旧记录+正确修订；若干净题也不会做，应先研究一般组合能力。若干净会做、加入修订历史才坏，再谈修订特有的干扰。单跳y能答对也不能单独定位stage，但能约束候选解释。

原计划Full/Whole-Early×Direct/OneLine四臂仍可比较联合策略。要判断缓存历史作用，应预先增加一个**Late+OneLine**：

| 条件 | 主要用途 |
|---|---|
| Full+Direct、Full+OneLine | 读出/分解策略增量 |
| Whole-Early+Direct、Whole-Early+OneLine | 与读出交互的联合干预 |
| Whole-Late+OneLine | 与同可见信息/位置/摘要的Early+OneLine比较编码历史 |

这成为80个短输出的五臂判别；保持有限单卡硬预算，先测一个平衡块，不能承诺两分钟全完成。若只保留四臂，就只报告联合策略效果，不宣称“KV不可替代”。之后若需要独立支持，再用已冻结12状态合流DAG，避免全格相乘。

主算法需要的消融应分清：核验提示本身、通用OneLine、明确子目标、版本/父依赖检查、局部重推、缓存重构。比较同信息、同工具、同总计算预算；给正确y/z的摘要须给其他方法同样信息并计费。C/W、并行兄弟分支、变量重名/换名、合法闭式计算和unknown都要保留。

## 8. P1标注应采纳的新点

采纳把传播失败分成旧值复用与新值错代；但修订有效性要另作一轴。

- E-Reuse：正确修订后实际将旧值/旧后代作前提使用，引用/否定不算。
- E-Misbind：正确修订后有明确错误绑定/无效代换证据；只缺一行推导不算，数字匹配只能算兼容签名。
- W型：本来正确却错误改口，可再带misbinding标签，但不进入“正确修订后的传播失败”分母。
- Unknown：局部约束、变量身份或后续使用不足以判断，保留未定。

并集为|Reuse|+|Misbind|−|Overlap|，不能直接相加。给出每题/每事件分母和观察窗口；不要从P0推定自然数据“漏掉一半”。新定义已保存为 `P1_LABEL_SCHEMA_V2.json`；原固定100题清单不改，当前没有百题语义发生率。

## 9. 正式评判指标：最终正确率是主指标

对每个数据集d：

\[
Acc_d=\frac1{N_d}\sum_i\mathbf1[\hat a_i\equiv a_i^*].
\]

数学等价/答案提取规则在试验前固定，格式合规另报；不可解析、超时、OOM的处理预先规定并保留分母。逐数据集报告Δaccuracy与配对正反变化，平均值不能掩盖某个数据集的退步。

| 层级 | 指标 | 用途 |
|---|---|---|
| 正式效果 | 最终答案accuracy；随机采样时pass@1 | 判断算法是否更会解题 |
| 同预算比较 | 固定总token/模型调用/工具权限或GPU计算预算下的accuracy曲线 | 排除单纯多花计算得到提升；同时给同质量的成本前沿 |
| 成本 | 完整端到端耗时、总生成/prefill/重算token、GPU-min、峰值和失败 | 包含核验、解析、被拒候选、回滚与重构；多卡墙钟与累计GPU-min分开 |
| 机制 | Reuse/Misbind/W伤害、绑定/父版本有效率、frontier完成率 | 解释改善来自哪里 |
| 训练诊断 | 独立NLL变化、梯度/q统计、一步预测残差 | 排查学习信号，不能代替最终答案指标 |

随机生成时若每题采样K次，平均每次成功率估计pass@1：先求每题成功次数/K再按题平均；pass@k则是k次中至少一次成功，计算预算不同，必须分列。多次采样不能取最好一次后仍称pass@1。greedy结果单列其采样协议。

同一模型checkpoint、采样、读出/评分、工具访问和预算必须明确；若方法用了精确验证器/解释器，强工具基线也要有同样权限。训练/调参的题不能重新包装成未见测试；当前历史300题仅作开发观察。最终论文应在未参与方法选择的题目上评测，按适用任务设置多数据集和模型规模，不预先铺开昂贵大队列。

## 10. 面向论文的推进判断

我们追求的是正效果：明确失效、提出最小新增机制、在强基线和消融下得到可复现增量。负结果用于筛掉无效模块；它不替代算法目标，也不意味着应不断换名或调种子。

当前主线优先“版本一致的局部重推”，训练赋权作为条件性第二路线。首先确认自然事件的可核验覆盖与一般组合失败基线，再做一个短配对；若文本工作帧足够，保留这个简单实现，只有它在强基线下仍有新的独立价值才扩大。若缓存重构确有额外收益，才设计更便宜的选择性重构。若训练只改善参考NLL或伤害W，不继续大训练。

拟议贡献必须落在前人模块之外的可核对象：修订后版本一致性、必要重推范围、可验证的有效状态转移及其成本/正确率增量。即使组合合理，也不能保证录用；目前尚无新算法的正式benchmark收益，不写已有高水平论文成果。
