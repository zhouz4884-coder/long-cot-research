# 3090 / V100 硬件建议评估与首轮预算

更新：2026-11-05；已补充主任务的实际调度和环境诊断。本文按本轮硬件建议的关键主张归纳，表中表述不是逐字引语；官方兼容证据及细节见 [V100 兼容报告](D:/ACL/research/direction_selection_20261105/agent_v100_compatibility.md)。最终运行结果以 RUN_STATUS_ZH.md 为准。

结论：3090 负责快速调试和当前模型条件下的主对照，V100 负责获得调度分配后的重复、重放与独立验证，这个分工合理。但它来自现有环境与实验成本的考虑，不能推成“V100 不能训练”“八卡已经八倍”或固定训练完成时间。本轮先用原始 Qwen3-4B 做不超过 1 GPU-hour 的机制接口检查，不需要先上 7B/14B、量化或训练。

## 哪些正确，哪些有条件，哪些夸大

| 建议中的主张 | 判断 | 对本任务的实际含义 |
|---|---|---|
| 3090 做交互调试，V100 并行承担可拆分的轨迹任务 | **方向正确** | 先建立单卡可重复任务，再按实际获批卡数分发；当前首轮只用一张卡运行一个 worker。V100 的 32 GB 容量可帮助缓存与重放，但不能代替兼容验收。 |
| V100 缺少原生 BF16，所以不能作为主训练卡 | **结论夸大** | V100 支持 FP16 混合精度训练与 loss scaling。能否承接某个训练取决于容量、数值稳定和实测速率；不能仅凭没有 BF16 判死。loss scaling 也不保证 BF16 预训练模型在 FP16 下稳定。见 [NVIDIA 训练指南](https://docs.nvidia.com/deeplearning/performance/mixed-precision-training/index.html)、[PyTorch AMP 数值边界](https://docs.pytorch.org/docs/2.8/amp.html#gradient-scaling)。 |
| V100 可以用 vLLM 提高吞吐 | **有条件** | 已核实的历史版本 0.8.5 包含 V100/Qwen3 支持，但 V100 对应 V0/XFormers；该版本依赖 torch 2.6.0，与当前 torch 2.4.1 不同。还受 CUDA、glibc 和扩展 ABI 约束。本轮沿用 Transformers eager，不向共享环境直接添加 vLLM。见 [GPU 要求](https://docs.vllm.ai/en/v0.8.5/getting_started/installation/gpu.html)、[版本依赖](https://github.com/vllm-project/vllm/blob/v0.8.5/requirements/cuda.txt)、[后端源码](https://github.com/vllm-project/vllm/blob/v0.8.5/vllm/platforms/cuda.py)。 |
| 八个 worker 就有八倍加速 | **只能作为理想同卡参照；作为承诺则夸大** | 理想八倍以单张同型号、同栈、相同任务速率为参照，还要求八张均获分配、负载可拆分。不能跳过每卡速度、长尾、排队、加载、I/O 和重试，也不能等同于比 3090 快八倍。本轮没有八倍实测结果。 |
| 2×24 GB 就是可自由使用的 48 GB；14B BF16 约 28 GB，余下 20 GB 全给 KV | **夸大** | 两张卡是独立内存，要显式切分模型并分别满足每卡峰值。即使只把权重按 28 GB 近似，剩余仍要容纳激活、通信/临时 buffer、CUDA context、logits 和安全余量；实际参数数及 GB/GiB 也须统一。官方推理实现通过 profile 扣除全部非 KV 开销。见 [vLLM 模型分片与内存预算实现](https://github.com/vllm-project/vllm/blob/v0.8.5/vllm/worker/worker.py)。 |
| AWQ/GPTQ 降低权重内存，能用于相同激活干预实验 | **省权重内存正确，干预等价有条件** | 量化会改变权重计算、kernel 和可能的缩放；须建立量化模型自身的无操作/未干预/干预对照，不能直接继承 BF16 激活结论。还要区分实现：vLLM 0.8.5 对 Volta 的表中 AWQ 不支持、GPTQ 支持、Marlin 不支持。见 [固定版本硬件表](https://docs.vllm.ai/en/v0.8.5/features/quantization/supported_hardware.html)、[AWQ](https://arxiv.org/abs/2306.00978)、[GPTQ](https://arxiv.org/abs/2210.17323)。 |
| 7B、8k–16k、1000–3000 样本可在 2–6 小时完成训练 | **当前没有证据支持时间保证** | 若每条确有 8192–16384 个处理 token，一轮就是 8.192M–49.152M token；还缺 epoch、训练方式、batch/累积、padding/packing、重算、有效 step time 和评估/保存成本。先测代表性短跑，再估时间，不能用样本数或生成吞吐直接换算训练小时。 |

## 可执行的分工

**3090：主对照与实现调试。** 使用已有授权环境和原始 Qwen3-4B，先验证 token/模板、整数 oracle、无操作干预以及前缀重放。跨平台主比较统一使用 FP16 eager 和相同 token IDs；原有 BF16 结果作为单独精度条件保留。第二张 3090 不在首轮预算中启用，不为了本 P0 搭建 14B 双卡切分。

**V100：调度内的可移植性检查与独立重复。** 待匹配gpublic条件的资源可分配时，申请一个小slot；通过 GPU 诊断后，重放同一份 token 前缀，在 V100 上重新构建 KV，再重复配对条件。只传 token/配置/模型内容身份，不把 3090 的 KV、激活或 RNG 状态当作 V100 原生状态。当前不再次等待GPU队列，先用空闲3090完成可独立开展的短实验，首轮不申请八个worker。

**CPU：准备和精确判定。** 模型通过 ModelScope 获取并逐文件核对固定 manifest；在 GPU 分配前完成可做的下载、tokenizer 检查、16 个合成案例的整数 oracle 和输入清单。若下载只能在 GPU 作业中完成，其分配时间也计入预算。16 个案例是 teacher-forced 合成机理接口集，不是自然长 CoT benchmark；填充长度也不等于增加了真实推理依赖深度。

## 首轮硬上限：60 GPU-min，含所有重试

预算按 `Σ(获分配 GPU 数 × 分配时长)` 计费；一次仅一张 GPU，GPU 分配期间的加载、预热、等待 I/O 和失败均计入。排队时间另列墙钟，不算已经消耗的 GPU 时间；不能因此承诺一小时墙钟内交付。若平台强制分配整节点，必须按全部分配 GPU 重新计费并缩短时长，不能用“只启动一个进程”把八卡分配算作单卡。

下表是跨平台阶段均可用时的预算上限；当前V100未获得分配，V100两项不执行、不预记成功，先完成3090项。

| 阶段 | 资源 | 最大预算 | 目的与边界 |
|---|---|---:|---|
| 环境/GPU smoke | 1×V100 | 10 GPU-min | 在正常 PBS 作业内确认环境、SM70、FP16、有限值、短推理和显存；未通过就停止模型实验并交付诊断。 |
| 对照与实现检查 | 1×3090 | 24 GPU-min | 固定案例、token 和条件；先无操作与重放检查，再做短配对。已有可复用的通过记录可减少此项，不挪用为大训练。 |
| 跨平台小重复 | 1×V100 | 20 GPU-min | 通过 smoke 后才执行，复用同样输入，在本平台重建 KV 并记录配对输出、峰值显存和时间。 |
| 失败/清理余量 | 至多 1×GPU | 6 GPU-min | 含已失败尝试和必要清理；未使用则不消耗。 |
| **总计** | **逐项累计** | **≤60 GPU-min = 1 GPU-hour** | 不并行申请多卡；若阶段超时或 admission 未解决，交付已完成的审计结果与未运行项。 |

这是工作量上限，不保证在预算内完成某个固定案例数量。首轮每条前缀最多 2k token、batch=1、每次 continuation 最多 64 token；不训练、不量化、不保留所有层完整 attention、不延长到 8k–16k。16 个案例按预先固定且组别交错的顺序运行；优先保持同一案例条件配对完整，不按生成是否答对筛选。

建议先比较“原上下文中明确修订”“去除旧错误分支后从 token 重算”“同路径无操作控制”，注意力干预只在其无操作验收通过后、用剩余额度开展。此处是待执行 P0 的预算建议；具体字段可见性与条件清单由主任务固定，不改既有冻结协议。达到预算即停止新增运行，保留完成配对、失败和未运行清单，不能把剩余样本补记为成功。

首轮应交付实际环境/模型身份、获批资源与 GPU-min、配对日志、精确 oracle 判定、显存峰值和真实时间。即使全部通过，也只支持“接口与局部机制值得继续验证”；16 个合成状态不能证明自然长链普遍改善、量化干预等价、八卡线性加速或固定训练小时。
