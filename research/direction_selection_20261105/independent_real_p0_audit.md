**审计通过；方法扩大暂为 NO-GO。** 保存的真实 Qwen3-4B / RTX 3090 / FP16 eager 结果支持“晚屏蔽不等于从开始屏蔽并重算”的缓存/读出差异，但不能支持“删掉旧分支即可安全纠错、优于一般屏蔽、节省实际显存或具备部署价值”。多个 C/W 控制被目标干预从正确改错，已经足以否定按 Wait 或人工分支标记无条件执行的安全主张。

## 数值独立复算

16 份 NPZ 各有五个 `float32[151936]` 数组，80 个数组全部有限。转换为 float64 后独立计算稳定 softmax、TV、JS、logit 最大差与相对 L2；与逐例 JSON 和 summary 共核对 144 组比较、576 个数值指标，最大绝对差 **8.34×10^-14**，低于预设核对容差 1×10^-10。

| 同位置、同可见 key 集的比较 | logit 最大差范围 | TV 范围 | 平均 TV | 首 token argmax 改变 |
|---|---:|---:|---:|---:|
| Target-Late / Target-Early | 2.09375–6.27344 | 0.07158–0.51129 | 0.29320 | 5/16 |
| Random-Late / Random-Early | 1.61719–6.78125 | 0.02076–0.50852 | 0.21743 | 2/16 |

这些是相同读出位置的全词表分布差，不是最终答对率，也不是“错误污染程度”标尺。随机屏蔽同样产生明显 early/late 差异，说明该缓存机制并不只存在于语义错误分支。

离线候选评分的完整 token logP 求和、去重角色和首 token 概率也做了记录一致性检查；float64 重算的首 token logP 与原 float32 记录最大差约 2.22×10^-5，此项没有混入上表 float64 指标的 1×10^-10 核对容差。后续 teacher-forced 位置的原始 logits 未保存，不能从这 16 份读出 NPZ 独立重建其全部 logP；本报告不把“求和一致”冒充独立重跑候选评分。原脚本分臂/分候选缓存隔离已在源代码审查中检查。

## 控制不是“16 例全部做过”

预声明的 E01、C01、W01 三例完整控制全部通过；其余 13 例的 `controls.passed` 是 **null / 未运行**，并非失败，也不能改写为 16/16 全部控制通过。逐例状态和全部原始 checks 已写入 JSON 审计文件。

| 控制项 | 三个控制状态的记录最大值 |
|---|---:|
| 同路径原始/early 重放与 sentinel 输出差 | 0 |
| 被屏蔽 key、未来 key 的 attention mass | 0 |

因此，主比较差值显著大于记录中的同路径零误差，也远大于 dense/cached 的最大 0.0625 shape 差。这里的 attention/KV 只有运行时归约结果，未保存全部张量，本地审计核对其内部一致性和源代码边界，不能声称重新做过模型前向。

新增的 target/random early-prefill 检查已在真实运行三个控制状态上通过：不仅后续读出禁读，前缀编码的幸存 U/R query 也不读取屏蔽列。这个结果修复了最初仅检查读出边界的控制盲区。

## 80 个输出与严格解析 0 的解释

已逐条查看全部 80 个原文，并原样保留在 JSON 审计的 `all_80_original_texts`。各臂原始 strict parser 都是 0/16 可解析：它只接受完整单整数，而输出均含句号或表达式/说明。**这说明原格式评分器不适配这些输出，绝不等于 80 道数学答案都错。** 原始分数保留；并行的 gold-blind posthoc 抽取应另列，不能覆盖/伪装成预注册主指标。

不依赖复杂抽取规则，也已有以下人工可直接核验的反例：

| 状态 | 题目定义的正确 z | Full 原文 | Target-Late 原文 | Target-Early 原文 |
|---|---:|---|---|---|
| C01：旧分支正确 | 31 | `31。` | `43。` | `37。` |
| C04：旧分支正确 | 20 | `20。` | `17-9=8。` | `17-9=8。` |
| W01：错误 Wait 修订 | 28 | `28。` | `11。` | `11。` |
| W03：错误 Wait 修订 | 121 | `121。` | `7*7=49。` | `49。` |

这不是根据 gold 重新挑样本运行；它们是固定 16 状态中原先设计的负控制。C/W 损害说明被屏蔽内容或其后继表示可能仍承担有用中间计算；简单的“旧分支被否定/含 Wait，所以删掉并重算一定更干净、更正确”解释不成立。

一个有助于理解读出指标的案例是 E02：late 与 early 可以有相同首 token argmax，但一个续写 `28*2=56。`，另一个续写 `2*(28-9)=2*19=38。`。所以只看首 token argmax 一致会漏掉后续行为变化；反过来，TV 大也不能自动推出正确性改变。

## NO-GO 应如何表述

推荐表述是：**“本轮通过了缓存禁读和重算一致性的接口控制，观察到了真实训练模型中的状态与读出差异；但未达到把该操作升级为自动纠错方法的门槛。固定负控制上存在明确伤害，随机屏蔽也有明显效应，故停止无条件 Wait/分支删除和效率主张的扩大实验。”**

对 early 比 late 更差的个别状态，应保留结果并解释为：重算改变的可能同时有错误和有用信息，去除历史影响并不等于朝正确答案移动；不回头把所有差异都叫数值 bug。本轮同路径控制为零，不能在没有新证据时用“FP16 随机噪声”抹掉反例。若 posthoc 汇总显示 early 在某一子组更好，也不能用该子组掩盖 C/W 的新增错误。

随机臂如果达到相同或更好的行为结果，最多说明一般屏蔽/重算、位置或重复文本效应可能足够；随机池只匹配 token 数、未匹配连续性/年龄，因此既不能据此认证“随机最好”，也不能据此认证“证伪语义特异性”。本轮没有内存压缩，也不能宣称省显存或加速。

仍可保留的研究问题是“可靠外部证伪成立时，如何在保留有用支持的同时恢复状态”。它需要新的可观察证伪边界和独立病例复核，不能由这次人工正确修订/强制干预直接推成在线系统。当前不建议训练、不追加大评测，也不因小子组阳性扩大预算。这个短 P0 已完成了应该完成的否证与诊断工作。
