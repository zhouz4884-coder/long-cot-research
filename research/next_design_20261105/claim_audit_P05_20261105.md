# P0.5 机制解释与设计审计

2026-11-05。本审计逐条读取原 16 个病例、实际 P/B/U/R/S、运行脚本和 80 个输出；用独立受限 AST 求值重建依赖图与正确/旧值/修订值，并核对旧文件运行前后 hash。仅使用本地 CPU 和 Python 标准库，未连接 GPU、未生成新模型输出、未改旧源或旧结果。用户新主张按主任务转述摘要审查，不冒充逐字引文。

**结论：暂不按当前 P0.5 方案跑 GPU。它的关键对照在原 16 例中不存在：每例都是 `x→y→z`，对 x 的完整依赖闭包就是整个数值分支，闭包之外的 `B_shared` 为零。** 可以把“修订值的变量错绑/遗漏复合运算”作为新假说，也可以另造确有独立支持的合流 DAG；不能先把这次失败解释成误删独立 y/z，再用这个解释设计一个预期会“严格证明半数原因”的实验。

## E02：28 的来源必须纠正

实际 P 保留：`x=7*4，y=x-9，z=2*y`。

实际 B：`x=24；因此 y=15，z=30。`

实际 U：`继续依据题目给定定义进行核算。`，重复四次，**没有 28，也没有任何数字或 x/y/z**。

实际 R：`Wait，重新计算应为 x=28。后续计算采用这个值。`

Full 为 `56。`；Target-Late 与 Random-Late 都为 `28*2=56。`；Target-Early 为 `2*(28-9)=2*19=38。`，Random-Early 也得到 38。

因此，28 是修订 x 的字面值，并非旧分支中的任何计算值。`28*2=56` 与“把新的 x 直接放进 z=2*y、跳过 y=x-9”相符。这个描述比“U 中旧 28 复活”更贴近数据，但仍不能仅靠文字反推出 attention/KV 的唯一来源。

还要区分 **U 的文字内容** 与 **U 的上下文化 KV**。文字无数字，不代表其旧 KV 完全不受 B 影响；稠密因果注意力允许 U 的状态读过旧 B。CPU/真实模型的一致性控制支持这种一般计算依赖可能存在，却没有定位到 E02 的“旧 28”，因为输入里根本不存在那个旧数。

显式式子与部分正确结果相关，值得以输出要求做干预。但现有实验没有随机指定“只给整数/写一行代入”，输出形式是结果的一部分，不能当作已识别的中介原因。更不能依据输出短就断言模型内部没有计算；一次 forward 的计算也包含多层网络，而不是一条算术指令。

## 闭包审计：当前 B_shared 为什么为空

独立 AST 审计在 **16/16** 得到同一个依赖结构：

`x = 常数表达式 → y = f(x) → z = g(y)`

如果撤回的是旧 x 的数值断言，则其传递闭包是 `{x,y,z}`。B 中恰好只有这三个数值断言，原 Target 也已经在 **16/16** 屏蔽了整个 B。

若“FaultOnly”只指 x 加直接派生 y，那么被留下的 z 仍然是经 y 传播的后代；对 E 组，它也实际都是错误旧值。若“FaultOnly”正确递归闭包，那么它与 WholeB 在数值断言内容上相同；余下的标点、`因此`、变量标签或符号骨架属于另一种结构提示对照，不能改称“独立 y/z”。

C 组旧 x 没错，所以旧 y/z 都是有用而正确的**依赖后代**；W 组是错误修订否定正确旧 x。它们的伤害说明错误的撤回决定会丢掉有用工作，**并不说明 y/z 与 x 无依赖**。若用隐藏 oracle label 跳过 C/W，得到的只能是带已知证伪标签的离线上界，不能当在线 Wait 触发器。

还有第三类对象应分开：`y=x-9`、`z=2*y` 这种题目给定的**规则**在 x 改值后仍然有效；`y=15`、`z=30` 这种旧具体值会失效。原 B 主要是具体数值，P 始终保留规则。若新方案保留/重复规则，研究问题应叫“维持变量映射与复合运算”，不能把规则和旧数值统称为独立铁证。

## 一个真正有 B_shared 的最小改造

可以新增一个独立根 r 和末端合流：

`r=4+5；x=7*4；y=x-9；u=2*y；z=u+r`。

人工旧记录为 `r=9；x=24；y=15；u=30；z=39`，共享可见修订只给 `x 应为 28`，评价器的正确结果是 r=9,x=28,y=19,u=38,z=47。

此时撤回旧 x 的闭包为 `{x,y,u,z}`，真正独立的 `B_shared={r=9}` 非空。最终 z 也是后代，不能因它是最终结论而留着。P 在所有臂中仍保留所有定义；不要为了让 r 显得必要而从 P 隐去定义，后者改变了任务和可用信息。

建议序列为：

`P | B_shared(r=9) | B_bad(x=24,y=15,u=30,z=39) | U | R | S`。

把共享 r 放在错误段之前，因果掩码保证其旧 KV 没读过后面的错误段。**如果把语义独立的 r 写在错误段之后，其旧 KV 仍可能读过错误段；语义 DAG 的独立性不等于 Transformer 缓存独立性。** 这种排列必须对幸存 r 重新 prefill，或另设受影响后继重算范围对照，才能称状态恢复。

最小比较可以只做四臂，并先固定一种输出要求：WholeB-Early、FaultClosure-Early、同保留预算的非语义控制、FaultClosure-Late。WholeB 与 FaultClosure 的差检验保留独立工作；FaultClosure-Early 与 Late 在**同可见 token、同原 position、同摘要**下检验缓存重算。两者不能用一个联合差值同时归因。全部保留 no-error/false-Wait 对照，结果只覆盖小合成状态，不外推自然推理。

保留 r 比 WholeB 多留若干 token，必须承认可见预算和冗余线索不同；需要同保留量、尽量同年龄/连续性控制。不能用“FaultOnly 比 WholeB 答对多”一个现象就认证语义独立性机制。

## 若现在只想检验变量错绑/输出格式

不需要假造 B_shared。可以在原 16 例上另立一个更窄的、冻结的 2×2：上下文 Full/WholeB-Early × 输出 DirectInteger/OneLineEquation。OneLineEquation 只要求按原题逐层代入，不提供任何新数值。两种格式都应重新跑其对应后缀，不能把旧 S 的结果和新提示当作同条件配对。

这最多检验“要求写出代入过程能否减少映射遗漏”，不能证明单 token forward 无计算能力。还需记录实际新 token 与时间：相同上限不等于相同实际计算量。首先固定输出格式做一次对照，或先固定恢复策略检验独立支持；不要把两种新改动全部一起加上再归一个原因。

另一个合法的小对照是重复 P 中已有的符号规则作为 scaffold，例如明确提醒 `y=x-9；z=2*y`，与同长度中性提示比较。它属于规则显著性/变量绑定，不是保留独立数值；Late/Fresh 两臂若比较缓存，必须看到完全相同的 scaffold。

## 正确摘要与信息泄露控制

- “保留原 y=15”是保留失效后代；“把 y 改为 19”是新算出一个正确中间值，二者不可混称恢复已有独立支持。
- 若摘要加入正确 y/z，这部分是 privileged 的新计算/验证信息。尤其给出正确 z 就直接给出答案；不能由收益推回“原失败因为丢支持”。
- 同一正确摘要应同时给 Late 和 Fresh 才能比较状态路径；另设不含新数值的摘要、只含原可观察修订的摘要，区分信息增量与重算增量。外部验证/重算成本必须计入。
- 已知题目 AST 可以合法给出依赖结构作为受控 oracle，但不能把这个 oracle 的闭包、正确值或标签偷换成尚不存在的在线检测器。
