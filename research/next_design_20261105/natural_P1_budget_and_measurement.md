# 自然长链 P1：预算、轨迹复用与统计审查

日期：2026-11-05。结论：**可以先复用已有轨迹做零新增 GPU 的观察性发生率审查；不能承诺新生成 50–100 条自然长链只用 15–20 GPU-min。100 条中少于 5 条的点估计可作工程停止线，但不能直接证明真实发生率低于 5%。32 条长链的一次梯度诊断可以准备，10 GPU-min 是否足够须先以明确配置测 1–2 条，且仅选择 ECN 尾部会产生选择偏差。**

## 3. 无答案泄露地标注三个不同事件

先明确：读取问题本身的数字和生成前缀不是标签泄露；把终答 Gold、未来轨迹、正确性列或 oracle 结论交给生成器/在线触发器则会改变任务。离线 Gold 可用于最终评分或明确的训练标签，但必须隔离，不能回写为线上可得证据。

| 标签 | 必须满足 | 不足以算事件的情形 |
|---|---|---|
| 数值修订 `R` | 同一实体/变量、同一作用域下存在原值 v_old 和后来的明确撤销/替换值 v_new；两个 span 可定位。 | 只出现 Wait；重新确认旧值；不同变量恰好不同数字；换单位/约定；近似精度变化；讨论尚未承诺的候选。 |
| 正确改错 `C` | 在原始题目约束下，可用明确局部计算/逻辑见证独立证明旧断言错、新断言对。记录 witness；确实不可判定则 unknown。 | 最终答案答对；新值在 Gold 中出现；模型自称 corrected；新值比旧值更高概率。 |
| 改对后复用旧值 `U` | 在已标 `C` 后，同实体的后续有效计算又实际采用 v_old，且影响一个派生量；记录复用式和依赖对象。 | 引用旧值以否定它；检查旧方案为何错；无关地方重现同数字；同一旧值在另一个变量上合法；仅最终答案碰巧等于旧值。 |

标注流程应可审计：

1. 导出白名单副本：问题、原生成文本/IDs、采样和 cap 元数据、源行 ID/hash；排除 `gold/solution/grade/correct`、强制终答、所有额外 probes/分支。不要让标注器直接接触带 Gold 的整行 JSON。
2. 第一阶段只看当前前缀，定位 `R` 的实体、原值、新值和旧/新 span，不看最终得分；不要用未来是否复发决定哪次修订“算修订”。第二阶段核验该局部数学断言，标 `C/incorrect_revision/unknown`，见证只依据题目约束和可核验中间关系。
3. 第三阶段读取后续窗口，定位 `U`，记录新值是否仍被使用、旧值是否仅被引用、是否有足够的依赖使用机会。最终任务评分由独立评分器最后 join，不能反向调事件规则。
4. 保存字符和 token 位置、作用域/实体 ID、v_old/v_new、验证式、后续复用式、观察窗口、cap、标注者与冲突处理。字符 span 到 token span 必须用固定 tokenizer 对齐验证，不按字符长度粗算。
5. 至少对所有阳性与 unknown 做独立复核，并对一批阴性盲复核；不因难标而静默删掉。工具或 LLM 建议只是候选，需原文证据；人工标注时间另记，不伪装成 GPU-min。

分别报告 `R/N`、`C/R_可判定`、`U/C_有充分观察`，同时给出对全部题的 `U/N`、unknown 数和各级分母。每题多次修订具有相关性，主比例以独立问题为单位；事件级结果另列，不能把一个题的二十次回看当二十个独立样本。更复杂的“合法改路”和仅能由最终 Gold 判定的步骤，先列 unknown，不强迫产生二元标签。

## 4. 观察结果不能归因于“旧 KV 污染”

看到 `C` 后出现 `U`，只证明一种文本行为。可能原因包括语言上下文中的旧值仍显著、局部算术能力不足、实体绑定错误、采样噪声、合理探索或真正受旧上下文影响的后续表征；观察本身不能区分。

本轮 P0 证明同 token/绝对位置下晚屏蔽与从 prefill 屏蔽重算的状态不同，但随机重算也会造成差异，并有正常病例受损；不能把自然文本 `U` 自动接到“旧 KV 是原因”的结论。将来需要同一冻结自然前缀、同读出/精度、无操作、位置/年龄/跨度匹配随机干预、相同预算重算的反事实；检测器准确率、理想 oracle 干预上界与真实触发后的端到端收益分别报告。

这与现有 62 篇地图中的相关边界一致：SCoRe/Satori 要同时关注改错与改坏；TAAR 已处理错前缀诊断/重启；CRV 将可预测与因果干预分开；memory rollback 的首次恢复不保证后续更少复发。这里只复用现有札记的证据边界，没有重新宣称逐篇全文复现。见 [模块评估](D:/ACL/research/long_cot_landscape_20261105/模块拆解与组合评估.md)、[关键阅读札记](D:/ACL/research/long_cot_landscape_20261105/关键论文阅读札记.md)。

## 5. cap/censor 必须进入分母与结论

先冻结要估的对象：例如“该模型在指定题池、原解码设置、最多 8192 token 下，观察到一次正确改错后，在原生终止或随后 512 token 内是否实际复用旧值”。它与“无限长链最终是否复发”不是一个比例。

长度 cap、超时、解析失败和无法核验的局部断言分别编码。若改对后只剩十个 token 就触达 cap，未看到复用不能记成充分窗口内的阴性；也不能只删除它以留下完整轨迹。可以同时报告按当前窗口可观察的下界、unknown 比例与最坏上界：总 N 题中 k 个已确认事件、u 个可能受截断/未知影响，简单范围为 `[k/N,(k+u)/N]`，再另给已可判定子集比例。这个范围不能消除标注错误或抽样偏差。

59/100 的 Omni boxed cap 表明只分析自然终止病例会强烈改变样本。长度与题目难度/纠错次数可能相关，不能无证据假设删失独立，也不应直接套生存分析得到无界发生率。bounded FULL16384 同样是有限参照；native 16k 的 11/29 cap 不能变成“其余不存在事件”。

新固定 100 条清单中的 15 条 cap 也必须保留。若它们都可能缺少所定义的事件观察窗口，即使其余没有确认事件，未观测部分也允许最高 15% 的简单最坏情形；不能直接用“0/100”二项上界替代这一缺失问题。实际 u 要按事件位置与预定观察窗口逐条判定，不能把全部 cap 一律判阳性或阴性。

## 6. “100 条低于 5% 就 kill”应怎样解释

如果意思是“该工程方向不值得继续投入”，可以预先把 `<5/100` 作为成本决策；但它不等于已统计排除真实发生率 5%。应先固定分母是全部题还是已正确改错事件、固定标签、一个题一个主要观察，并处理 censor/unknown，再使用二项区间。下表是独立、完整、准确标注问题的 **95% 单侧 Clopper–Pearson 上界**，由本次 CPU 直接反演二项 CDF 计算；不是已经测得的事件率。

| 观察到的事件 | 点估计 | 真实率的单侧 95% 上界 |
|---:|---:|---:|
| 0/32 | 0% | 8.94% |
| 0/50 | 0% | 5.82% |
| 0/100 | 0% | 2.95% |
| 1/100 | 1% | 4.66% |
| 2/100 | 2% | 6.16% |
| 4/100 | 4% | 8.92% |

所以在这些前提下，100 题中 0 或 1 次可支持“上界低于 5%”；2–4 次仍包含 5%。如果真实率正好 5%，`观察次数<5` 的规则有 **43.60%** 概率判 kill。50 题零次也不能在此置信水平排除 5%。这些频率解释不把 95% 置信度读成“真实率有 95% 概率在区间内”。精确区间依据见 [NIST 二项比例区间说明](https://www.itl.nist.gov/div898/handbook/prc/section2/prc241.htm)。

如果按阶段反复查看 20、50、100 题并择时停，普通固定样本 95% 区间不自动保留同样覆盖保证。可以固定最终 N 和预定检查点，把中途结果用于成本停止、最终作为探索性结果；若需要随时有效的推断，须另外预注册相应序贯方法。不要在本小实验中事后改阈值来挽救方向。

本表按独立同分布二项观测的超总体目标计算；若目标仅是当前固定有限题池、采用无放回抽样，则应使用相应的超几何/有限总体区间。同题多个 seed、同链多个事件不满足这里的独立题假定；任何区间都不直接提供跨模型、跨题域或部署保证。

## 7. 15–20 GPU-min 能买到什么

**复用并离线标注 50–100 条旧轨迹可用 0 新增 GPU-min**，但 CPU/人工时间不保证只需十五分钟；旧数据来源、看过与否、截断和标签质量仍需交代。

若每条新轨迹实际生成 8k–16k token，50–100 题在 15–20 单卡 GPU-min 内完成，需要约 **341–1820 generated token/s** 的对应组合，尚未含加载/评分/失败。历史本地记录为：

| 历史组 | 累计请求 wall 记录 / 串行等价分钟 | 说明 |
|---|---:|---|
| Omni boxed 100 题 | 36,398.41 秒 = 606.64 单卡请求分钟 | 664,228 个 trace token，另有答案/协议开销；不是当前新栈测速。 |
| native 29 题，8k 条件 | 10,235.10 秒 = 170.58 单卡请求分钟 | 有 16 题 cap。 |
| native 29 题，16k 条件 | 16,047.38 秒 = 267.46 单卡请求分钟 | 有 11 题 cap。 |

这里将每条绑定单卡请求的 `wall_ms` 相加，不是多卡整体墙钟，也不是对历史完整作业分配时长/实付 GPU-hour 的重新审计；额外加载、空闲和排队并未包含。它们不能当本轮预计耗时，但足以说明“新生 50–100 条长链、15–20 GPU-min”还没有实证支撑。若用多卡减少墙钟，GPU-min 要按全部卡累加，不能把八卡二十分钟写成二十 GPU-min。

建议把新增 GPU 留给**少量已冻结的配对重放/长上下文前向 smoke**：先 1–2 条测 prefill、峰值内存、实际后端和短 continuation，再由真实每条成本决定剩余条数。15–20 GPU-min 是硬预算，不是保证完成 100 条的目标。预算内仅完成少数案例也应记录全部失败与未运行项，不按答对或最短样本补齐“100 条”。

## 8. 32 条 long-CoT 的一次 forward/backward：可准备，不先承诺十分钟

先把“一次”说清楚：batch=32 的一次完整前后向、microbatch=1 累积 32 次后的一次 optimizer update，以及对同一 graph 分别求多个损失梯度，是不同工作量和内存配置。32×8k/16k 已是 262,144/524,288 个 teacher-forced token；10 分钟要求约 437/874 processed token/s，加载、重算和梯度分解还会提高实际要求。自回归生成 token/s 不能代替这一吞吐。

当前 P0 只有前向，没有长链反向证据。若全参数混合精度 Adam，FP16 权重/梯度、FP32 master weights 和两份优化器矩就约每参数 16 bytes，4B 约 64 GB，尚未含激活；普通单卡 24 GB 全参路线不可由 4B 推理能装下推得。LoRA/冻结参数、优化器状态 dtype、梯度 checkpointing、attention kernel、损失读出位置和 microbatch 必须明确。3090 可尝试的 FA2 也不能未经控制当成 V100 eager 的同一数值条件。

一次聚合 backward 能诊断给定目标的 loss/梯度是否有限、每层范数、耗时/峰值，**不能单独分解“尾部梯度”和“正确答案锚点梯度”的夹角或证明尾部污染训练**。至少需要分离损失项的 `autograd.grad`/多个反向或其他明确代理；一轮前向复用 graph 不等于只有一次反向，内存与时间要重算。一小步训练后的同样本 loss 降低也不证明泛化收益；若做一步更新比较，需相同初值、匹配 token/范数/学习率的控制与未参与更新的问题，实际成本可能超过十分钟。

因此建议十 GPU-min 的边界为：先 1 条、再 2 条 microbatch=1 的工程入场，检查 finite/显存/时间；若外推后 32 条可在预算内且留出保存/清理余量，再完成累积诊断，否则如实交付已测成本，不挪用未批预算。不要为完成条数缩成与声称的 long-CoT 不同的短链而不标明。

## 9. 32 个 ECN 尾部样本是否有选择偏差

**有，若用它来推断自然长链总体。** STOP 的 ECN 按“具有完整回答功能且答案正确”的最早节点定义，训练构造本来就依赖成功轨迹和正确答案判断；它不是部署时免费 oracle。只挑“存在 ECN 且尾巴长”的 32 条，必然排除无正确结论、晚纠错、被 cap 截断以及从未成功的链，也预先提高了后缀看似冗余的概率。见本轮核对的 [STOP 官方条目](https://aclanthology.org/2026.findings-emnlp.672/) 与现有阅读札记。

这类 32 条仍可回答一个**条件问题**：“在已知正确结论后仍继续生成的这个子群里，特定尾部 loss 对局部梯度有何影响？”不能回答“所有长链尾部都污染训练”，更不能从删尾后变短推断学得更好。若资源只允许 32 条，应保留它的条件定位和全部筛选分母；或从完整固定题池中按 ECN存在/不存在、长/短后缀作预定分层，记录各层总体权重、未知与 cap。分层取样不能直接报未加权总体率。

以 Gold 标注 ECN、答案锚点或构造训练目标可以作为明确的离线训练信息；不要把这些标签作为原模型自然纠错触发输入。更新诊断用的 32 条不能同时充当最终效果测试集。当前没有必要恢复任何旧早停流程：这里的 ECN 只用于审查尾部训练假设，不产生在线退出策略。

## 10. 本轮可执行决定

1. **现在可做：** 冻结一个历史探索题池与标签规范，CPU 导出 Gold 隔离视图、先独立标注自然修订/局部正确性/后续旧值复用，保留 cap 和 unknown；现有轨迹足够开始，不需要重新生成 100 条。
2. **满足前提再做：** 有可靠标注与值得研究的事件后，才申请有限的 3090 配对重放；对 KV 归因保持反事实要求，不把自然发生率当方法成功。
3. **单列而不承诺：** 32 条梯度诊断先确认可执行目标、参数范围、loss 分解与样本选择，再按 1–2 条实测入场；10 GPU-min 作为硬上限，未测前不承诺完成。
4. **允许 NO-GO：** 事件在预定题池/窗口下罕见、unknown 太多无法判定、触发不可靠或随机对照同样有效，都足以停止扩大；报告证据和限制，不把它改写成正算法结论。

本报告提供的是独立可行性和测量设计审查，未执行上述新增标注、生成、训练或干预；新增 GPU 消耗为零。
