## 2. 交互很大，增量却很小

2×2描述性交互为：

`(12−0−11+8)/16 = 9/16 = 0.5625`。

但联合臂只比更强的FullOneLine多 **1/16**。E组交互为1/8，C/W分别为1；大部分交互来自OneLine弥补了WholeEarlyDirect对本来正确C/W的破坏。

一般地，若联合和OneLine单独同为b，而mask-only=a低于Direct=c，则交互是`(b−a)−(b−c)=c−a>0`，联合相对OneLine仍无增量。因此“正交互”不自动证明两模块都必需，更不证明两个神经错误源正交。

本轮联合相对FullOneLine的实际配对为：

- E07、C04：FullOneLine已经写出正确z，但64token截在最终答案标记；EarlyOneLine更简短，完成可解析交付。
- C03：FullOneLine正确30，EarlyOneLine变56，新增真实的已交付错误。

故净+1主要涉及预算/交付差异，不能归因成已经消除旧中间值复制或改善算术机制。LateOneLine→EarlyOneLine有4个主评分修复：E04/E07/C04是上述类似的触顶/解析差异；W03是已交付49→121的条件性修复。没有据此追加token或重跑。

## 3. 对四项建议的判断

1. **保留互补假说，停止预判必然互补。** 本轮FullOneLine已能在E02/E03等题从原题重算，不表现为一写y就必抄旧y。没有做head定位；不能给出induction机制结论。
2. **保留机制候选，但完整计费。** 本轮完成80个Y/Z条件面板、220个去重完整候选，额外220次candidate forward/410个teacher-forced token，以及64次独立前缀probe forward/2744个输入token。Direct-Z精确复用了16次已有readout；其余并非零成本。辅助诊断只有8题，不能填满16题。
3. **采用crop的前缀复用性质，收紧回滚保证。** 精确HF4.55.2 tiny CPU的5个seed中，crop后前缀与同路径续写logits完全等价；但仍需恢复logits、RNG、输入和解码状态，也没有普遍W零伤害保证。本GPU五臂不包含Gate/crop算法。
4. **采用数值候选索引，不自动生成可信闭包。** 固定100题提取12560个候选边；全部语义状态仍为UNKNOWN_UNREVIEWED。100题均出现“同值有多个潜在来源”的情况；表面风险flag不是错误率，没有flag也不是verified。没有报告自然复发率。

## 4. 其他有用观察

本轮FullDirect的16个输出全部等于旧B记录的终值；C/W中旧终值本来正确，所以它们答对不等于模型验证了错误R。WholeEarlyDirect则全部错误，说明删除可直接读出的结论后，当前简短读出协议没有稳定完成组合计算。

OneLine自由生成共2520token，两个Direct臂共98token；全体2618token。它的改进伴随更多实际计算，不能称与Direct耗时相同。各臂上限相同不意味着实际花费相同；本轮共享prefill/检查点和大量离线诊断，也不是独立完整请求的速度排行榜。

## 6. 后续算法应怎样收紧

继续保留“版本一致的局部重推”为候选主线，但**Whole mask本身尚无可靠独立增益，缓存操作后置**。更值得测试的新增机制是：核验后只安排失效前沿、固定目标变量/父版本、避免从根重复展开，并确保最终答案能在预算内交付。

下一小轮若开展，应比较同样精简的普通计算提示、Self-Ask式子目标提示和版本/父依赖工作帧，给相同核验信息与预算。这样能区分新增版本约束与纯粹少写字的作用；不能直接把本轮cap修复包装成新数学推理能力。

自然P1的语义事件与P-only/P+R基础能力仍是待完成项；词法候选图不能代替它们。当前不继续补齐诊断、不进入训练或正式多数据集大评测。本轮有限短试与独立分析已经完成，后续方法依这些结果重新预声明。
