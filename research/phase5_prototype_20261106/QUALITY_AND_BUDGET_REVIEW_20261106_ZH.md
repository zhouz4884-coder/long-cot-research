# Phase5 首轮原型：质量与预算双轨审查

2026-11-06。只读核对 Phase5 计划草稿及 P0.5 原数据。本页是回答后的实验方案建议，没有运行模型、GPU、远程或修改旧资料；GitHub 是否完成应由主任务核验远端 commit/tree 与交付清单，不能仅凭“仓库已创建”推定上传完成。

**建议先做小型四原型对比，但先让模型自然完成，给宽松保护上限；再独立比较同预算曲线。不要再用 64-token 截断制造主要优势。** 最近 P0.5 的 8/11/0/12/8 是旧 Whole-mask/读出结果，不是本 Phase5 新算法成绩。

## 1. 首轮到底是什么算法

第一轮不训练、不做 KV mask/crop，不运行完整逐节点外部验收循环。更准确的名称是 **“共享根核验信息的版本/前沿提示原型”**：

- G 只根据可用原始定义核验 x/r 等根值；accepted、rejected、no-change、unknown 分开。它不认证旧 y/z，更不能看到 E/C/W 标签后直接输出旧 z。
- 所有方法获得同一个 P、旧断言、候选 R、相同 G 输出与结构/工具权限；正确派生 y/z 不放进提示。
- 普通 Direct、紧凑表达式、普通步进和版本工作帧是四种组织方式，使用同一模型和新请求前缀。所谓无 KV 操作，是不操纵现有 cache；正常 prompt prefill 仍有成本。

四臂建议为：

| 原型 | 要求 |
|---|---|
| G+Direct | 利用同样信息，直接交付最终答案；不把旧 z 伪装成 G 已认证的结果 |
| G+Compact | 一条紧凑数值代入式后给最终答案，避免冗长逐项展开 |
| G+Stepwise | 普通父值代入/分步提示；第一轮同样只生成一次，不冒称已复现某篇 Self-Ask 的多轮系统 |
| G+VersionFrame | 显式列值版本、dirty/unknown 与下一就绪目标，要求按当前父值重推；第一轮只是提示，没有外部 checker 逐步阻断错误 |

只有以后实现“逐节点提议→精确/可靠检查→接受或拒绝→更新证书与前沿”，才能称作完整的逐步验收执行算法。写出整数不等于数值已被认证。

## 2. 可以展示的思想和公式

令规则图为 \(F=(V,E)\)，\(C\) 是变量到当前有证书的值/版本的映射，\(S\) 为通过核验且实际改变的根变量集合。

\[
I=\operatorname{Desc}^{*}_{F}(S),\qquad
N=\bigl(\operatorname{Anc}^{*}_{F}(z)\cap(I\cup U)\bigr)\setminus\operatorname{dom}(C),
\]

其中 \(U\) 是尚未认证的相关变量，\(\operatorname{Anc}^{*}(z)\) 包含 z 自身。撤回的是 I 内旧版本的值，不是不变的定义规则；G 当前只认证根，所以不能把旧 y/z 从 U 中自动删掉。

\[
\mathcal F(C,N)=\{v\in N:\operatorname{Parents}_{F}(v)\subseteq\operatorname{dom}(C)\text{，且父版本均当前有效}\}.
\]

这是真正的“可执行前沿”：可包含多个兄弟，不能只处理第一个 y 然后跳到汇合 z。工作帧把目标、规则、当前父值/版本写清楚，减少错绑和漏传；这是待测效果，不是已证明的内部阶段指针。

未来完整执行器在节点验收通过后才写入 \(C[v]\leftarrow(\hat v,k,\mathrm{certificate})\)，重新计算前沿；失败或 unknown 不推进。**当前单次提示原型不具备这个闭环，不能直接引用其 soundness 命题作为原型保证。**

## 3. 双轨而非“设上限/完全不设”二选一

### A：质量优先、自然结束

先回答：各原型在能够正常完成时谁更可靠。以 EOS 或预先定义的完整提交结束为主，设置宽松保护上限防循环/失控。对这些短合成题，可建议起步用 512 个新 token 作为保护，而不是主要打分目标；具体值需在新协议中先冻结。

不能在“最终答案：1”刚出现时立即停，因为它可能还要继续成为 121。提交需要有完整字段边界/终止符。触到保护上限的输出仍记 capped，不能算自然结束；若保护顶成为常见事件，本轮就没有回答自然完成质量问题，应另开已声明的预算调整，而非暗改旧分数。

“不设任何上限”并不更科学：仍受上下文长度、资源、墙钟、无穷续写和工具循环约束。应取消过紧的研究瓶颈，保留清楚标记的工程保护。实验累计 GPU 总限仍独立存在，本页不授权或扩大它。

### B：相同预算下的质量—成本前沿

自然完成质量摸清后，再预先选少量预算点，例如 64/128/256，报告各方法最终交付正确率、capped/unknown/未解析、C/W 新损害和完整成本。不能只挑候选赢、基线尚未提交的 64 点。

若全部方法的提示和策略不感知预算、没有预算相关强制结束/提交行为，固定贪婪轨迹可在多个前缀预算做离线交付统计；但这只是轨迹重放，不自动提供各点独立在线延迟。若方法改变工作帧、保留窗或动作以适应预算，则需要按那些新条件实际评估，不能用同一轨迹冒充。

支持算法价值的证据应是相对最强简单基线的 Pareto 改善或给定可接受质量下的真实成本下降，而不是“生成字数短了”或“正好跨过一处人为截断”。

## 4. 五种预算必须分账

1. **自由生成 token**：模型实际采出的输出，作为原始 \(B_{gen}\) 单列。
2. **控制注入/强制提交 token**：控制器写入的 frame、标签、追问和提交窗不是免费。生成期间注入的位置应计入输出位置预算；作为输入的指令/状态则计 prompt prefill。
3. **工具/G**：解析、根核验、计算器/外部验证调用及时间，各臂工具权限一致；symbolic oracle 不当成模型免费能力。
4. **重算/失败分支**：重新 prefill、被拒绝候选、追问与重试的全部前向/输入 token 和时间，不因最后没交付而抹掉。
5. **实验累计 GPU 限额**：包括加载、哈希、控制、全部方法与失败尝试的单卡总占用，是研究资源上限，不是每题 max_new_tokens。

请求成本可以按时间写为

\[
T_{req}=T_{parse/G}+T_{prefill}+T_{decode}+T_{forced}+T_{tools}+T_{retry/rebuild}.
\]

计数时避免重复相加同一工具/前向时间。生成 token、prefill token 和 CPU 工具调用不是等价计算单位，完整墙钟为主，token 向量辅助；一次模型加载另报为共享实验开销或声明的 cold-start 成本。

## 5. 小型能力控制与首轮规模

建议先用六个状态：一个线性程序、一个合流程序，各含 E/C/W。这只是两个程序的开发控制，不是六个独立问题。四原型共 24 个 free 输出；不加 Y/Z 候选评分，不加新训练或 KV 消融。

P-only 与 P+R 用同一紧凑输出契约作小型能力控制，**不预设 100%**，也不冒充与共享 G 主方法相同信息的排名基线。如果每组三种状态确实共享同一 P，且 E/C 的 P+R 字面相同，可按精确输入 ID 去重：2 个 P-only、4 个不同 P+R，共 6 个额外输出，总计 30。若输入不同就不能按语义猜测去重。

能力控制不输入正确派生值。P-only 衡量原始组合题能力，P+R 包括 W 的错误修订，用来测提示干扰；两者都不能唯一证明“问题只在状态管理”。原 16 例和已看过结果仍属于开发资料，不能在后续当独立确认集。

先冻结模板、G 权限、保护上限、解析器、完成规则、六状态顺序和实验总限，再运行这一个小比较。总限不足则保留完整配对和未跑清单，不通过缩短基线或挑易样本完成表格。之后若要看预算曲线或完整逐步执行器，应根据本轮结果另行决定，避免一次叠加多个未测模块。

## 6. 回答用户时应清楚说明

可以说：“下一步是无训练、无 KV 操作的小型同权限方法比较。先允许自然完成，避免 64 截断主导结果；再看同预算曲线。版本工作帧目前是原型，不预填效果。”

不能说：“已经实现完整认证算法”“G 验过 x/r 所以旧 y/z 安全”“不设上限就更公平”“64 下胜出证明算法更会推理”“强制尾窗不花预算”。P0.5 已显示 3 例正确 z 因提交格式未完成而失分，另有未完成算式；这正是需要双轨评估，而不是继续利用截断制造优势的理由。
