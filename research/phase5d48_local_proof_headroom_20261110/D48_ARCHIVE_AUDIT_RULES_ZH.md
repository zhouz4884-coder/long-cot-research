# D4.8 归档观察和准入规则

题组独立审查者只看原题。完整求解者各自锁定同权限普通结果。归档审查者只接收所分配题目的思维文本、原题和身份回执。冻结其断言位置、解释、是否可核验和核验成本，再解封官方键、最终答复及源评分。对实现者已经推导过的题，优先换给另一名审查者。归档侦察者另有解答预暴露，只负责入库和出处核对。[题组冻结](D48_QUESTION_FREEZE.json)

归档按预先选中的同名模型配置和 draw 0 各取一条。不能证明原始服务器修订一致时按年份分层，原生生成内容字段只能用于文本证据。缺少明确 EOS、原始 token、logits 或 RNG 时相应列保持未知，不认证可以精确重放或通过自然 EOS。缺失、错题、无独立思维、缺终答和未知边界分别计数。

每题先只看前 12,000 个 Unicode 字符或更短的完整可用思维，以可核对的段落或句子边界定位明确数学断言。剩余思维如有复查单列，不用后文授权早期断言。早期与补充审查均可报告不支持域、仅提问或试探、换目标、分支专属前提、缺合法反例、已经自行修订。锁定最早可反驳断言时保存字符位置、原始断言和前缀哈希。没有独立验证其含义和作用域的断言保留未授权。公开记录用结构化派生结果和哈希，原文保存在本地。

用于核验的赋值只来自原题和该可见前缀。证书检查 \(\operatorname{Domain}(w)\land A(w)\land\neg B(w)\)，只否定这个箭头。出现局部错误、错误持续、能启动修复、最终答错是四个不同指标。按独立题目数计算准入。即使发现真反例，如果普通完整解已经以同权限给出，且在测得的工作范围内仍便宜，该题没有证明端到端策略残余。

代表性的题面局部检查与完整 CPU 计算先独立实跑。核验准备、形式化、人工时间、模型归档的已付 token 和新 GPU 分列。不要把不同操作加成 FLOP，也不把归档缺失的成本当作 0。若强普通完整控制覆盖这批任务，可以记录真实的中途错法，阶段仍以未通过修复准入收尾。
