# D5.0 工作记录

| 遇到的问题 | 尝试 | 决策 |
|---|---|---|
| 前序赋权只有理论及代数控制 | 核对原梯度审查与当前仓库，沿用独立主批、方向批、留出以及同范数诊断。 | 本轮以真实检查点的实际一步结果为主，代理与生成正确率分开。 |
| 作者 VCORE 与公平控制不同 | 回查固定源码、论文一步式、固定温度、损失比例缩放和反向调用。 | 全链梯度效用是主要对照，统一 KL 和 SGD 是本轮控制。作者全套训练效果不从这一小试外推。 |
| 自然数据的版本、模型和终止不一致 | 固定 BrUMO 2025 的 QED-Nano 第 0 抽、30 道独立题，三分割各 10。只有 29 道能分出思维文本。 | 来源模型与训练模型分别报告。归档没有原生 EOS 或模型状态。只在盲态观察窗审查局部断言，完整文本另测 tokenizer 长度。 |
| 真实长链不能随意切短以适应显存 | 用已核对的 Qwen3-4B tokenizer 重新编码整段可用思维。 | 26 条长度落在 40,960 容量内，3 条超出，1 条缺思维。超长原样保留，适配容量与 GPU 激活显存是两件事。 |
| 需要在真实模型上查数值，同时隔离留出 | 冻结 9 道开发题和 30 道独立可控题。统一配对续写长度，所求新数值没有出现在各前缀里。 | 可控侧只衡量真实模型对已知状态操纵的一步响应，和自然发生率分开。先使用开发包选择数值口径，正式 H 单独封存。 |
| 远端 Python 版本与本机不同 | 只读校验模型时，Python 3.10 缺少较新的文件摘要函数。改成块式 SHA-256，重新读取所有权重、配置和 tokenizer。 | 两张 RTX 3090 在检查时有空闲显存，现有 Qwen3-4B 与冻结 tokenizer 匹配。启动前再逐字节读回。 |
| 同 KL 与同范数不保证同功能变化 | CPU 小模型逐 token 精确梯度比较中央差分，另外核对参数恢复、梯度符号、零步重复及实际付费前向和反向。 | 八项测试通过。保持统一初值、实际更新和多尺度探针，正式阈值预先冻结。 |
| 三态方向确实不同，留出效果仍可能相抵 | 同一张 3090 先跑开发控制，再跑独立正式留出，比较同学习率和同参数范数，逐题读出初值、零步、实际变化与控制差。 | T 在 E 的两个方向相反，W04 两种比较均下降。平均线性残差很小，保留实际负结果。 |
| 自然前缀修对后仍可能答错 | 锁定七条局部角色后开启末答与键，先严格独立解析，再单列简写分式复核。另按原题做有限验证。 | P24 在下游漏掉合法路径。严格 5 对、1 错、1 未知，后验修复解析不重写主分。 |
